# FormaDoc toolbar behavior audit

**Reviewed:** 2026-08-27

**Competitor:** FormaDoc PDF editor

**Local product:** Akkivo

## Scope and method

This audit covers the complete toolbar requested for comparison. FormaDoc was inspected in the in-app browser with an already-loaded PDF. Each tool was activated in sequence, its visible controls and state changes were recorded, and temporary annotations were undone. One `[audit]` text change had to be saved inside FormaDoc's Edit Text session to exit that mode and remains in the currently open draft. The competitor's top-level Save and Download actions were not used, so no claim is made that the draft was persisted remotely.

Akkivo was checked through both its live local editor and its current React and TypeScript implementation. The comparison focuses on observable interaction design, not visual similarity alone.

Validation labels used below:

- **Validated:** the control produced an observable result in the document or opened its complete workflow.
- **UI confirmed:** the mode and options were inspected, but browser automation could not reliably complete the page gesture.
- **Not exercised:** the behavior was intentionally left untouched because it could alter existing document content.

## Supporting controls and workflows

### Document chrome

- The top navigation exposes Search, Print, Save, and Download separately from editing tools.
- A persistent thumbnail rail is roughly 300 px wide and has a resizable divider. The selected thumbnail receives a purple outline and numbered pill.
- A floating bottom navigator contains current page, previous and next page, total page count, multi-select, zoom out, zoom in, and fit-page controls.
- Active tools receive a clear pressed state. Incompatible tools can become disabled during modal editing modes such as Edit Text.

### Page management

The Manage Pages modal provides New Page, Delete Pages, Duplicate, Rotate Left, Rotate Right, Move, Move Before, Move After, and More. It displays the document's page list and ends with Cancel, Save As, and Save actions.

### Notes

The Note tool exposes colors Yellow, Orange, Red, Fuchsia, Blue, and Green. Its icon choices are Comment, Right Pointer, Right Arrow, Checkmark, Ellipse, Cross, Insert Text, New Paragraph, Text Note, Paragraph, Help, Star, and Key.

### Shape variants

The Shapes group contains Line, Arrow, Rectangle, Ellipse, Polygon, Polyline, Cloudy Rectangle, Dashed Rectangle, Cloudy Ellipse, Dashed Ellipse, and Dashed Polygon.

## Major UI and UX patterns

1. **The secondary toolbar is the core interaction pattern.** The primary row chooses the mode. A stable, full-width row directly below it exposes only the controls relevant to that mode. Edit Text is the strongest example.
2. **Creation behavior is tool-specific and immediate.** Draw, line, callout, link, and crop use page gestures. Check and Cross insert an object immediately. Signature and Stamp use a modal. Image opens file selection immediately.
3. **Mode state is always visible.** Pressed and disabled states communicate which workflow owns the canvas, especially while editing existing PDF text.
4. **Selection is concrete.** Objects receive visible bounds, handles, and delete or note actions. Lines expose endpoint handles. Crop uses handles plus an outside mask.
5. **Commit boundaries are explicit.** Crop separates selection from application. Edit Text prompts before leaving with unsaved changes. Forms use Done. Modal tools use Done or Cancel.
6. **Control vocabulary is reused.** Color, opacity, thickness, fonts, size presets, alignment, and Delete appear in consistent positions and wording across tool contexts.
7. **Navigation remains available while editing.** Page thumbnails and bottom navigation coexist with the tool state instead of being replaced by it.

## Observed FormaDoc quirks

- Editing existing PDF text produced visible overlap and unexpected reordering during one test. The feature is powerful, but its source-text replacement was not visually lossless.
- Redo after a text edit rebuilt the document view and returned navigation to page 1.
- Automated Draw and freehand Highlight gestures produced dots rather than representative strokes. The mode and history behavior were confirmed, but stroke quality was not established by this audit.
- Redact Text, Redact Area, and Highlight Text could not be fully applied through browser automation. Their controls and active modes were inspected, so they should not be treated as end-to-end validated.
- Image placement reused a previously available image during the browser session rather than consistently presenting a fresh selection flow.
- Check Mark and Cross insert very large centered objects immediately. This is fast, but can feel surprising compared with placement-first tools.
- The browser console showed unrelated authentication network noise, duplicate rich-text framework warnings, and deprecated image-gallery property warnings. These did not block the tested editor workflows.

## Akkivo parity summary

### Implemented toolbar shell

- A compact document bar now holds the Akkivo identity, current filename, search, Properties, Apply, and Export.
- A dedicated editing strip exposes every production-ready high-frequency tool directly and keeps working variants in accessible split menus.
- Selection controls now occupy the stable secondary row rather than floating over document content.
- The fixed right Inspector has been replaced by a closed-by-default Properties drawer, so the canvas keeps the full working width until advanced controls are requested.
- Crop, Redact Text/Area, Draw, freehand Highlight, Erase, Cross, Callout, and the expanded Forms palette are real toolbar actions, not visual placeholders.

### Strong parity

- Undo and redo state model
- Add Text plus select-first, edit-second source-text replacement
- Typed, drawn, uploaded, and reusable signatures
- Line and other shapes
- Image placement
- Stamp and link annotations
- A broad set of form fields

### Improved in this pass

- Text editing now uses a stable contextual row with Bold, Italic, size, font, color, link, move, duplicate, delete, and Done.
- Forms, Images, Annotate, and Shapes now use split controls with explicit variant triggers, active variant labels, expanded state, Escape dismissal, and outside-click dismissal.
- Undo and Redo now have platform-standard keyboard shortcuts that preserve native field and content-editable history.
- Draw and Ink now capture and preview the real pointer path and commit one undoable, exportable stroke.
- Crop mutates real PDF page boxes and participates in byte-aware Undo/Redo, persisted session history, and a bounded snapshot budget.
- Erase performs exact stroke-level splitting, while freehand preview and committed point counts remain bounded for very long gestures.
- Callout insertion is immediate and its leader anchor/elbow are draggable. Cross is an immediate page-center action.
- Forms export as interactive AcroForm controls across nine variants with deeper value, behavior, and appearance settings.

### Partial parity

- Text has a stable editing row and preserves recoverable embedded typography. Arbitrary mixed-style blocks, affine transforms, vertical text, Type3 fonts, and missing subset glyphs still require a fallback because the source PDF does not always expose reusable editing metadata.
- Redact Text and Redact Area are dedicated visual workflows, but they do not remove underlying PDF objects. Secure content sanitization remains open.
- Erase has a visible fixed-radius cursor, but its thickness is not yet user-configurable.
- Check Mark is still placement-first, while FormaDoc inserts it immediately like Cross.
- Form signature boxes are text-field placeholders, not cryptographic PDF signature fields. Vertical alignment, creator/custom metadata, and several FormaDoc border styles remain open.
- Callout text is edited through Properties rather than opening a rich-text editor immediately on placement.

### Missing parity

- Secure redaction that removes or irreversibly sanitizes underlying PDF content
- A genuine PDF signature field and FormaDoc's deeper custom field metadata
- User-adjustable eraser thickness and immediate Check Mark insertion
- Callout rich-text entry directly on placement

## Prioritized implementation recommendations

### P0. Make existing editing feel coherent

1. Extend the contextual row from Text to selected shapes, redactions, callouts, ink, and form controls using the same shared vocabulary.
2. Add keyboard arrow navigation within grouped-tool menus and verify split controls at narrow viewport widths.
3. Add a user-facing eraser thickness control and make Check Mark follow the same immediate insertion rule as Cross.

### P1. Close high-value annotation gaps

1. Design a secure redaction pipeline only after proving that removed text/images cannot be recovered from exported bytes.
2. Add direct rich-text editing to a newly inserted Callout while keeping its draggable leader geometry.
3. Replace the signature text fallback with a genuine PDF signature field, with clear signing versus placeholder semantics.
4. Add the remaining field metadata and appearance variants only where they survive export across major PDF readers.

### P2. Add deeper document operations

1. Consolidate common color, opacity, border, font, alignment, note, duplicate, and delete controls into reusable contextual-toolbar primitives.
2. Add browser coverage for each new tool's activation, creation, selection, contextual controls, cancel, Undo/Redo, session restore, and exported PDF result.
3. Test cropped, rotated, and mixed-size documents against Acrobat, Preview, and PDF.js before treating cross-reader fidelity as complete.

## Production-readiness acceptance checks

- Every toolbar action has a visible idle, hover, pressed, focus, disabled, and selected state.
- Every mode can be exited with Escape without losing unrelated edits.
- Pointer tools preview during movement and create exactly one history entry per completed gesture.
- Text editing preserves source positioning, wrapping, font fallback, and visual masking across zoom levels and export.
- Destructive actions have clear scope and an undo path. Visual redaction must never be presented as irreversible content sanitization.
- Contextual toolbars remain usable on narrow screens through wrapping or horizontal scrolling without covering the selected object.
- All controls have stable accessible names, keyboard focus order, and menu-expanded state.
- A saved and reopened PDF preserves the visible result, link targets, form metadata, crop boxes, and annotation geometry.
